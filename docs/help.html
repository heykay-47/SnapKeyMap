Getting started

You need a Find X9 and either Shizuku or a USB cable and computer. No root or paid tools are required. Other devices and ColorOS versions may behave differently.

  1. Install the app

    Download SnapKeyMap-*.apk from the latest release and open it. Allow your browser or file manager to install apps when Android asks. No GitHub account is needed.

  2. Enable accessibility

    In SnapKey Map, tap Open settings and turn on its accessibility service. If Android blocks the switch, open SnapKey Map's App info, tap the three-dot menu, choose Allow restricted settings, then try again.

  3. Grant log access

    Use a computer or Shizuku below. Reopen SnapKey Map and choose Allow when Android asks for access to device logs.

  4. Teach and assign

    Set Oppo's own Snap Key action to None in phone Settings. Teach the key in SnapKey Map, choose your actions, and test each gesture. Allow notifications and background activity so the app can tell you when detection pauses.

With a computer

This grants log access once. Android can still ask for device-log consent when the reader reconnects.

  1. Download Google's free SDK Platform-Tools and unzip them.
  2. On the phone, open Settings > About device > Version. Tap the build or version number seven times to enable Developer options.
  3. Turn on USB debugging in Developer options.
  4. Connect the phone with a USB cable. Accept the debugging prompt on the phone.
  5. Open a terminal in the unzipped platform-tools folder and run:
adb shell pm grant com.heykay.snapkeymap android.permission.READ_LOGS

In Windows PowerShell, use .\adb instead of adb if it is not on your PATH. Success normally returns to the command prompt without a message.

Reopen SnapKey Map and allow device logs. The grant survives restarts and app updates. If the command reports GRANT_RUNTIME_PERMISSIONS, use the ColorOS fix below.

Without a computer

  1. Install Shizuku and follow its Wireless debugging pairing and start instructions. Wireless debugging requires Android 11 or later.
  2. Once Shizuku is running, open SnapKey Map's log-access screen. Tap Grant with Shizuku and allow the Shizuku permission request. The button appears only while Shizuku is running.
  3. Allow device log access when Android asks. You do not need to keep Shizuku running after the grant.

If ColorOS blocks the grant, follow the permission monitoring fix, restart the phone, start Shizuku again, and retry.

Manual fallback with aShell

If needed, open aShell while Shizuku is running and allow aShell to use Shizuku. Run the same permission grant directly in its shell, without the adb shell prefix:

pm grant com.heykay.snapkeymap android.permission.READ_LOGS

Return to SnapKey Map and allow device logs. aShell cannot bypass ColorOS permission monitoring either.

Teaching the key

First set Settings > Snap Key to None. Otherwise Oppo's action may run as well as yours.

In SnapKey Map, start Teach the app your Snap Key. Follow the hands-off prompt, press the key three times when asked, then hold it once. Keep the app open throughout.

To repeat setup, choose Teach the Snap Key again on the home screen. Your action assignments stay unchanged. After updating from v1.0.3 or earlier, teach it again before testing. Older calibration can select a message that matches only key-down events and merges double presses. Current learning prefers the known Oppo press-and-release source when present.

Choosing actions

Tap Press, Double press, or Press & hold on the home screen. Choose an app, supported shortcut, link, or device action. Test it and check the Last: text in the Ready card.

  • A double-press assignment adds a 350 ms wait after release before the single-press action runs.
  • The known Find X9 log reports press and release edges. Other learned log formats need repeated events while held to detect a hold.
  • The shortcut picker supports apps that offer ACTION_CREATE_SHORTCUT, not every pinned shortcut. Try a deep link instead. Direct-dial shortcuts are not supported because the app has no calling permission.
  • Silent mode and Do Not Disturb need notification policy access. Without it, the ringer action cycles between ring and vibrate.
  • Android permissions, device support, and the lock screen still apply. The app cannot bypass the lock screen. Screen-off detection and background reliability depend on ColorOS.

Troubleshooting

Paused after a restart

Reopen SnapKey Map and allow device logs again. If it shows Paused, tap Connect. You do not need to repeat the ADB grant unless you uninstalled the app or revoked the permission.

If you declined the prompt, wait a minute before retrying. Check that accessibility remains enabled and ColorOS allows background activity.

The key is not detected

Set Oppo's own Snap Key action to None, then choose Teach the Snap Key again. Confirm that the service is enabled and device logs are allowed. Test with the app open and check Last:.

A double press is read as two singles

Set Oppo's action to None. Update to the latest app and teach the key again. Older learning can miss the release events needed to separate gestures. v1.0.3 and later fix duplicate events in the recorded Find X9 format.

Keep SnapKey Map open and check Last: after double-pressing. If it says press, detection did not recognise the double press. If it says double press, check the assignment and that the chosen app is still installed.

ColorOS keeps closing the app

Open App info > Battery and allow background activity. Turn off battery optimisation for SnapKey Map, using the home screen's background activity prompt if available. Allow notifications so you can see when detection pauses. These settings reduce interruptions, but do not guarantee background or screen-off detection.

The grant is refused with GRANT_RUNTIME_PERMISSIONS

An error containing Neither user 2000 and GRANT_RUNTIME_PERMISSIONS means ColorOS is blocking shell permission grants. This affects both ADB and Shizuku.

  1. Open Developer options and turn on Disable permission monitoring. Newer firmware may call it Disable system optimization.
  2. If neither appears, temporarily change the system language to English, United States and reopen Developer options.
  3. Read the warning before accepting. This relaxes manufacturer restrictions and may increase background power use.
  4. RESTART the phone. On ColorOS 16 the change only takes effect after a restart. Reconnecting the cable is not enough.
  5. Retry the grant command. For Shizuku, start it again first.

Names and locations vary by firmware. These device notes were checked on a Find X9 running ColorOS 16, CPH2797_16.0.10.600. If the setting is missing, include your ColorOS version in a report.

Still stuck? Open an issue with the app version, ColorOS version, assignments, and Last: text. Do not share an unfiltered system log. It can contain sensitive information.

Is it safe?

READ_LOGS granted over adb is a powerful permission. Give it only to apps you trust. It grants access to the whole live system log, not just the Snap Key.

What stays on the phone

The app declares no INTERNET permission. It does not send logs or settings off the phone. Apps and websites you open through an action handle their own data and have their own privacy policies.

The reader checks incoming log lines in memory. It does not save a log file. Outside teaching, matching lines drive key detection and other lines are discarded.

During teaching, it temporarily keeps observations in memory: an arrival time, log tag, normalized message, and writer UID. Runs of message digits are replaced with #, and the message is trimmed and limited to 160 characters. This does not remove all sensitive text. Tags and UIDs are retained. Accessibility key-code observations can also be kept during teaching.

After learning, the app saves one selected log signature, not the collected log: the tag, normalized message, and writer UID, plus hold detection and release timing settings. If Android supplies a usable key event instead, it saves the key and scan codes rather than a log signature. The observation list is not written to storage and is released after learning finishes or is cancelled.

How key lines are checked

A learned key line must match the writer UID recorded during teaching, as well as the tag and normalized message. The known Oppo key line is accepted only from the system UID, 1000. Other apps cannot fake a Snap Key press just by writing the same line under their own UID.

Accessibility and settings

The accessibility service can receive supported key events and perform device actions. Its configuration sets canRetrieveWindowContent="false", so it cannot read window content.

Settings use private app storage. Android backup is disabled with allowBackup="false". Mappings and the learned key are not included in Android backups.

Declared permissions

The app's permission list contains:

  • Read device logs (READ_LOGS): detect the Snap Key in the live system log.
  • Vibrate (VIBRATE): give feedback when an assigned action runs.
  • Show notifications (POST_NOTIFICATIONS): tell you when detection pauses.
  • Access notification policy (ACCESS_NOTIFICATION_POLICY): use Do Not Disturb and silent-mode controls.
  • Ask to ignore battery optimisation (REQUEST_IGNORE_BATTERY_OPTIMIZATIONS): request background operation.
  • Shizuku API access (moe.shizuku.manager.permission.API_V23): lets the app ask Shizuku for the one-time log permission grant. The app uses it only for that grant, not for log reading or mapped actions. Shizuku need not stay running afterwards.
  • Internal receiver permission (com.heykay.snapkeymap.DYNAMIC_RECEIVER_NOT_EXPORTED_PERMISSION): added by the AndroidX library. Only this app holds it, and it keeps other apps from sending broadcasts to the app's private receivers.

The code is open source. You can inspect the implementation and build it yourself.

Updates and removal

Install the new APK over the old app. Do not uninstall first. Updates signed with the same key keep settings and the granted log permission. Android may still ask for device-log consent when the reader reconnects.

Uninstalling removes the app's settings and log permission. If you reinstall, grant log access and teach the key again.
